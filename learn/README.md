# Whistle 源码研读站

一套面向开发者的 Whistle 源码学习站点，基于 VitePress 构建，通过 GitHub Actions 自动发布到 GitHub Pages。

- 源码基线：分支 `guide`，提交 `3b85cebc4`，`whistle v2.10.13`；其后提交仅更新文档站，业务源码（`lib/`、`bin/`、`biz/` 等）零改动，站内行号仍有效
- 站点地址：`https://<owner>.github.io/whistle/`（`base` 固定为 `/whistle/`）
- 内容：41 篇正文 + 18 张自绘 SVG 架构图，主线逐级递进，外加「工程场景」与「概念精解」两大专题
- 定位：讲「实现原理 + 源码细节 + 领域知识 + 工程场景 + 概念精解」，与仓库根目录 `docs/` 的官方使用文档互补
- 工程场景专题：`scenarios/` 下 10 篇，从真实工程问题出发，向上追溯整体业务设计思想、向下定位到源码路径与行号；场景与规则均取自官方使用文档、集成测试与 CGI 实现
- 概念精解专题：`concepts/` 下 11 篇，用「通俗定义 + 形象类比 + 源码落点 + 设计取舍 + 易混淆 + 工程实例」拆解约 360 个专业名词，含 83 组辨析、一次 HTTPS 请求的 28 步贯通案例与全量术语索引
- 章节编号：41 篇正文按阅读顺序统一编号 `01`–`41`，侧栏每项前的两位数字即该编号

## 章节编号与编排

全站只有**一套**连续编号 `01`–`41`，配置集中在 `.vitepress/config.mts` 的侧栏数组；分组标题用「板块名 · 编号范围」标出顺序（如「领域基础 · 02–05」），不再使用带数字的层级标签。概念精解板块内部的「入口与报文 / 加密与信任 / 运行时与数据 / 规则 / 扩展」是依赖顺序的说明，同样不是章节编号。新增或调整章节时，需同步更新侧栏编号、`guide/orientation.md` 的编号分布表、首页 `index.md` 的卡片范围，以及对应专题总览里的目录序号。

| 板块 | 编号 | 篇数 |
|---|---|---|
| 开始之前 | 01 | 1 |
| 领域基础 | 02–05 | 4 |
| 全局架构 | 06–08 | 3 |
| 核心链路 | 09–12 | 4 |
| 模块深潜 | 13–17 | 5 |
| 专题 · 工程场景 | 18–27 | 10 |
| 进阶实践 | 28–30 | 3 |
| 概念精解 · 由词及理 | 31–41 | 11 |

工程场景插在模块深潜与进阶实践之间，用于横向复用前四层机制；概念精解放末尾，兼顾系统通读与按词回查。两者都纳入连续编号，避免出现「有些章节有编号、有些没有」或专题另起一套编号。

## 本地开发

```bash
cd learn
npm ci           # 首次或 lock 文件变化后
npm run dev      # 本地预览，默认 http://localhost:5173/whistle/
npm run build    # 产出到 learn/.vitepress/dist
npm run preview  # 预览构建产物
```

Node.js 20 及以上（VitePress 1.6 要求 Node 18+，CI 固定使用 20）。

## 写作约定

**表格列宽**：普通表格限制在 4 列以内、单元格文字尽量短。需要精确控制列宽时，用自定义容器包裹 markdown 表格：

```markdown
::: cols 18|32|34|16
| 类别 | 代表指令 | 作用 | 实现文件 |
|---|---|---|---|
| 请求改写 | `reqHeaders` | 改请求头 | `inspectors/req.js` |
:::
```

容器会把百分比写成 CSS 变量（`--c1` … `--c6`），由 `custom.css` 中的 `.tbl-cols table` 规则应用为固定列宽；窄屏自动退回横向滚动。

**图片**：全部放在 `public/diagrams/`，正文用 `![图注](/diagrams/xxx.svg)` 引用（VitePress 构建时自动补 base）。图片点击会打开查看器，支持滚轮缩放、按住拖拽、双击切换 1:1、`0` 键回到原始尺寸、`f` 适应窗口、`Esc` 关闭。SVG 必须显式声明 `width` / `height` / `viewBox`，否则查看器无法取得固有尺寸。

排版约定（新增或改动 SVG 时逐项检查）：分组大框内的卡片四边至少留 16px，不得越出父框；顶部对齐的左右并列区域，底边也要对齐（若右列由多块组成，以最下方一块为准）；同一列内卡片间距保持等距；色条若与卡片同宽同高，用 `clipPath` 按卡片圆角裁剪，避免从圆角处凸出。改完用无头浏览器按原始尺寸渲染截图复核，缩略图里看不出的贴边问题在 1:1 下会很明显。

**源码引用**：一律使用仓库相对路径加行号，例如 `lib/tunnel.js:168-213`，不要写本机绝对路径。

**工程场景文档模板**：`scenarios/` 下每篇（总览页除外）固定使用「场景与痛点 → 可复制的配置 → 背后的设计思想 → 源码链路 → 边界与坑 → 小结 → 下一步」七段结构。其中「设计思想」必须链接回前面的架构/领域章节，「源码链路」必须链接到核心链路/模块章节并给出 `路径:行号`，以此保证每个场景都双向可追溯。配置与命令需注明来源（`docs/docs/` 文档、`test/` 用例或源码），不得凭常识编造。

**概念词条卡片**：`concepts/` 下每个核心词条用「一句话定义 → 打个比方 → 在 Whistle 里（路径:行号）→ 为什么这样设计 → 容易混淆 → 工程中的样子」六段展开；次要词条用 4 列速览表覆盖。每篇另需「本层概念地图 / 与工程实际结合 / 常见误解 / 小结 / 下一步」。目标是建立理解，不是罗列定义，因此不限制篇幅。

**新增文档**：把 markdown 放入对应目录后，在 `.vitepress/config.mts` 的侧栏数组里补一条；正文第一行必须写与 frontmatter `title` 一致的 `# 一级标题`（VitePress 不会用 frontmatter 自动渲染 h1）。如需使用 `::: cols`，无需额外配置。

## 学习笔记功能

站点内置笔记系统，代码在 `.vitepress/theme/notes/`，纯前端、零后端依赖。

**三种笔记**：选中一段文字后点浮动条记「选区笔记」；鼠标移到标题、段落、列表项、代码块、表格等要素左侧点 ✎ 记「要素笔记」；或点抽屉底部按钮记「整篇文档笔记」。选区笔记用字符偏移 + 引用文本 + 前后文指纹锚定，文档小幅改动仍能还原；刷新与 SPA 切换后会重建高亮。

**高效记录**：选中文字后浮动条提供「普通 / 重点 / 疑问 / 待办」四个一键标记，点一下就生成带原文引用的分类笔记，也可点「写笔记…」进入完整编辑器。编辑器支持标签切换、插入原文、按模板起稿（疑问带「待查证」清单）、自动记录所属章节、编辑 / 分栏 / 预览三种模式、字数统计与未保存草稿恢复。自动记录文档标题与最近标题，回看时知道这条笔记属于哪一节。

**查看与复习**：抽屉内可全文搜索、按标签筛选、切换最新/最早排序、展开或收起长笔记；「本篇 / 全部」两档按文档分组。每条笔记可定位原文、标记「已掌握」。**正文里的高亮可以直接点击**，会打开抽屉并定位到对应笔记；鼠标悬停笔记卡片会临时强调原文。「复习」页把笔记变成回想卡片：先看引用与出处，点一下再显示内容，支持上一条/下一条/随机与掌握标记。快捷键：`N` 新建、`/` 搜索、`Esc` 关闭、编辑器内 `Ctrl/⌘ + Enter` 保存。

**Markdown + 富文本**：编辑器提供粗体、斜体、行内代码、链接、标题、列表、待办、引用、分隔线工具栏；预览与笔记列表都渲染为富文本。高亮按标签分色（普通黄、重点橙、疑问紫、待办蓝、心得绿）。渲染前统一做 HTML 转义，只输出白名单标签，链接限定 http/https/mailto/相对路径。账号页可导出 JSON 或按文档分组的 Markdown 文件。

**按 GitHub 账号存储**（关键设计）：笔记不存在站点仓库里，而是存在**使用者自己 GitHub 账号的私有 Gist**（文件 `whistle-study-notes.json`）。身份由令牌通过 `GET /user` 解析，本地缓存按 `login` 分键，因此不同账号的数据天然隔离，不会串号。站点只需静态托管，无需数据库或 OAuth 后端。

使用者配置步骤：

1. 打开 [创建令牌](https://github.com/settings/tokens/new?scopes=gist&description=Whistle%20Study%20Notes) 页面，生成 **classic PAT**，权限**只勾选 `gist`**，不要勾选其它项。
2. 在站点右下角点「笔记」→「账号」→ 粘贴令牌 →「校验并连接」。
3. 页面会显示 GitHub 账号与同步状态；之后每次改动会在 1.8 秒后自动同步，也可点「同步」立即推送。换设备时输入同一令牌即可继续。

令牌只保存在当前浏览器的 `localStorage`，请求只发往 `api.github.com`；站点仓库、构建日志、Pages 产物都不含任何令牌。未连接账号时笔记仍可离线使用，数据保存在本机并明确标注「仅本机保存」，连接后自动合并到 Gist（同一条笔记以 `updatedAt` 较新者为准）。账号页可导出全部笔记为 JSON。

> 私有（secret）Gist 不会出现在公开列表，但知道链接的人仍可访问，请勿在其中存放密码等敏感信息。若未来要改成「一键 GitHub 登录」，需要额外部署一个持有 OAuth App 私钥的令牌交换服务，纯静态 Pages 无法安全内置 `client_secret`。

## 部署

工作流：`.github/workflows/deploy-learn.yml`。

触发条件：向 `guide` / `master` / `main` 推送且改动包含 `learn/**` 或工作流文件本身；也可在 Actions 页面手动 `Run workflow`。

流程：`actions/checkout` → `setup-node`（缓存 `learn/package-lock.json`）→ `npm ci --prefix learn` → `npm run build --prefix learn` → `configure-pages` → `upload-pages-artifact`（`learn/.vitepress/dist`）→ `deploy-pages`。使用官方 Pages 部署通道，无需 `gh-pages` 分支，也无需在仓库里存 token。

**首次启用只需一次设置**：仓库 → Settings → Pages → Build and deployment → Source 选择 **GitHub Actions**。之后每次推送会自动构建发布。

> 若把站点发布到个人主页仓库（`*.github.io`）或使用自定义域名，需同步修改 `config.mts` 里的 `BASE`，并视情况调整工作流中的 `path` 与 Pages 设置。

## 注意事项

- 站点内容与源码版本绑定；升级 Whistle 后请核对文档中的路径、行号与默认值。
- HTTPS 中间人相关内容仅用于调试自己有权调试的流量，请勿在生产环境或他人设备上滥用。
