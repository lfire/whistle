# 工程场景总览：从问题到设计思想，再到代码

读完了原有五层，很多人仍会在真实工程里卡住：知道 `host` 怎么解析，却不知道把整站代理到本地 dev server 时排除规则该怎么写；知道 `file` 会在 handler 里短路，却不知道接口尚未就绪时如何把 Mock 稳定固化下来。原有五层按「领域基础 → 全局架构 → 核心链路 → 模块深潜 → 进阶实践」纵向展开，回答的是「这段代码实现什么」；新增的「工程场景」层换一个方向，从真实工程问题出发，向上追溯到整体业务设计思想，向下追溯到工程实现代码细节。它插在「模块深潜」与「进阶实践」之间，是一组横向专题：每个场景都能在官方文档、集成测试或源码 CGI 中找到真实出处，读完不仅会配规则，还能说清这条规则为何这样落地、边界在哪里。

## 追溯方法：五个层次

本层每篇文档都按同一条链展开，读者可以把它当成一把尺子，去量任何一个新问题。

1. **工程问题**：谁、在什么系统约束下、遇到什么具体现象。场景不凭常识编造，一律来自 `docs/docs/` 的使用文档、`test/` 的集成测试或 `biz/webui/cgi-bin/` 的真实工作流。
2. **设计原则**：这个问题之所以被这样解决，背后是 Whistle 的哪条整体取舍。原则不是口号，必须能链接回站内已有章节，例如 [观测不改道](/core/capture-data)、[顺序即优先级](/modules/rules-engine)、[默认透传、显式才解密](/core/connect-mitm)。
3. **内核机制**：原则落到哪一层实现——入口中间件链、规则编译与匹配、协议分桶、handler 短路，还是 service 子进程。
4. **源码位置**：机制对应的 `lib/xxx.js:行号`，并链接到对应的核心链路或模块章节，例如 [一次 HTTP 代理请求的旅程](/core/http-request)、[规则引擎](/modules/rules-engine)。
5. **边界**：官方 FAQ 或源码阈值划定的失效条件，例如 2MB 合并上限、600 条抓包缓存、100 次重放上限。

对应到文档结构，就是固定小节「场景与痛点 → 可复制的配置 → 背后的设计思想 → 源码链路 → 边界与坑」。前三步回答「为什么」，后两步回答「凭什么」。把这条链走通，规则就不再是需要背下的字符串，而是能从设计推出来、又能被源码验证的结论。

## 素材来源

本层的场景与规则全部有据可查，来源限定为三类，不引入外部臆测；结论与全站一致，以 `guide` 分支 `3b85cebc4`（v2.10.13）的源码为准，其后提交仅涉及文档站、业务源码零改动。

- **官方使用文档 `docs/docs/`**：`rules/` 100 篇、`gui/` 11 篇、`extensions/` 4 篇，加根下 `getting-started.md`、`faq.md`、`mobile.md`、`cli.md`、`index.md` 共 5 篇，合计 120 篇，提供规则写法、界面操作与官方明确的注意事项。
- **集成测试 `test/`**：`test/index.test.js` 与 `test/units/` 下 82 个 units，用来验证「某条规则真的会这样走」，例如 `test/units/composer.test.js` 直接向 `cgi-bin/composer` 连续 POST 构造请求。
- **真实 CGI 工作流 `biz/webui/cgi-bin/`**：文件名即接口名，例如 `get-data.js`、`get-matched-rules.js`、`sessions.js`，把界面上的一次点击对应到服务端的一段代码。

需要提醒的是，官方示例个别存在笔误：`docs/docs/rules/enable.md:82` 的 `www.example.com enale://https` 应为 `enable://https`（官方笔误，本站以正确写法为准），`docs/docs/faq.md:71` 又把 `w2 start` 漏成 `2 start`（应为 `w2 start`）。本站一律以源码为准：遇到文档与实现不一致时，先核对 `lib/` 下的解析逻辑，再决定规则该怎么写。「以源码为准」也是本层区别于官方使用文档的根本分工。

## 小结

- 新增这一层，是为了补上「会用规则」与「懂设计、能定位源码」之间的空白，方向与原有五层纵向递进互补。
- 追溯方法固定为五步：工程问题 → 设计原则 → 内核机制 → 源码位置 → 边界，文档结构与之逐一对应。
- 十条设计原则是本层的共用索引，既有「观测不改道」这类取值，也有「内存有界」「约定优于配置」这类工程约束。
- 9 篇文档按 6 类问题组织，场景来自 120 篇官方文档、82 个测试单元与真实 CGI 工作流，文档笔误以源码校正。
