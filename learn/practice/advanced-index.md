# 高级层 · 从会用到能改、能集成、能讲清

::: tip 先修知识
已完成 [综合通关项目](/practice/final-project) 并在[能力自评矩阵](/practice/final-project#能力自评矩阵) 全部打勾，即能独立、灵活地把 Whistle 用到真实工作。高级层不再教「怎么点界面」，而是要求你**改动工具本身、把它接进自己的系统、对方案负责，并讲清机制**。需要一台能跑 Node.js 的机器（`node -v` 能输出版本号），但**不需要预先会写 Node 脚本**：A1 只用 `grep` 与断点，A2/A3 给可直接照抄的最小代码，A4/A5 只用命令行与文档。
:::

## 本关的学习目标（可验收）

读完能说出五类高级能力各自对应哪一份工件、最终认证要求哪几份证据；并能指出自己当前缺哪一类。做到这三条即达成——本页是地图，具体能力由 A1–A5 逐关验收。

## 什么叫「高级应用水准」

「会用」是能按需求写规则并验证；「高级」是下面五件事都能独立完成，且每件都留下**别人可以复核的工件**：

| 等级 | 能独立完成什么 | 关卡 | 工件 |
|---|---|---|---|
| A1 读得懂 | 带着一个现象钻进源码，定位到具体函数，并用一个可运行实验验证自己的理解 | [A1 读源码](/practice/a1-source) | 源码定位记录 + 断点/日志证据 + 预测对照 |
| A2 改得动 | 写出一个最小插件，安装后让它在请求链路上产生可观察效果 | [A2 写插件](/practice/a2-plugin) | 插件目录 + 安装输出 + 效果证据 |
| A3 接得进 | 把 Whistle 当作库嵌进自己的 Node 进程，用事件与断言验证规则命中 | [A3 内嵌集成](/practice/a3-embed) | 可运行脚本 + 测试输出 |
| A4 管得住 | 设计一套多人共用的规则集方案，处理分组、冲突与回滚 | [A4 协作方案](/practice/a4-collab) | 两份规则集 + diff + 冲突证据 + 回滚记录 |
| A5 说得清 | 量化代理开销、给出合规结论，并把「为什么」讲给一个会追问的人 | [A5 性能、合规与讲解](/practice/a5-perf-compliance) | 耗时数据表 + 合规清单 + 一页讲解稿与追问答案 |

高级层的验收**不接受自评打勾**：每一关都要产出上表最后一列的工件，并在最后的[高级认证](/practice/advanced-index#高级认证)里被逐份核对。

## 与前两层的关系

| 你已有的能力 | 高级层把它推到哪一步 |
|---|---|
| 会写规则并验证生效 | A1：知道规则在哪个函数被编译、在哪一步被求值；能用断点看到 `req.rules` |
| 会用 01–41 的机制篇查名词 | A1、A5：把「查到」变成「能预测并验证」 |
| 会 `.whistle.js` + `w2 add` 导入规则集 | A4：处理多人同时改、冲突谁生效、改错怎么回滚 |
| 会按现象排障六步 | A5：判断「这件事该不该用代理」并量化它的代价 |
| 会自己设计规则集（阶段六开放题） | A2、A3：把规则集升级成插件与内嵌服务 |
| 会清场 | A5：把清场写成合规结论，而不是个人习惯 |

01–41 源码研读在这里从「按需回查」变成**主要教材**：A1 直接读 `lib/rules/rules.js`，A2 对照 [16 插件系统](/modules/plugins)，A3 对照 [26 自动化](/scenarios/automation)，A5 对照 [27 边界与合规](/scenarios/boundaries)。

## 学习顺序

[A1 读源码](/practice/a1-source) → [A2 写插件](/practice/a2-plugin) → [A3 内嵌集成](/practice/a3-embed) → [A4 协作方案](/practice/a4-collab) → [A5 性能、合规与讲解](/practice/a5-perf-compliance) → [高级认证](/practice/advanced-index#高级认证)。

每关仍沿用训练关的九格结构，但「验收」一律要求工件，且新增「隔日复核」：把工件放一天后只照工件重跑一次，能复现才算掌握。

## 高级认证

**只有同时满足下面四条，才能有理有据地声称达到高级 Whistle 应用水准**：

1. **能力链完整**：从 [第 0 站](/guide/quickstart) 到 A5，逐关的「晋级标准」都有可观察证据，没有跳关。
2. **五份工件齐备**：A1 源码定位记录、A2 插件目录与效果、A3 可运行脚本与测试输出、A4 规则集 diff 与回滚记录、A5 耗时数据与讲解稿，缺一不可。
3. **隔日复核通过**：不看教程，只照五份工件把 A1–A5 的关键动作各重跑一次，记录哪一步卡住、怎么解决；全部一次跑通才算过关。**卡住不算失败**：按记录回到对应关卡重做「变式」，补进工件后再复核一次即可，这正是复核的意义。
4. **能被追问**：对下面三个问题各写一段能被同行检验的回答，且每段都要指向具体源码或具体实验，不许只写结论：
   - 为什么装了根证书仍可能看不到 HTTPS 明文？ decryption 判定发生在哪一段？
   - 为什么改一行规则会导致整份规则集重新编译？这对多人协作意味着什么？
   - 什么时候不该用 Whistle？给出至少三个可判断的触发条件与替代手段。

**认证记录模板**（自己填，作为最终证据）：

```txt
第 0 站 → L1 → … → L5 → 通关项目：逐关证据 = …
A1 工件：…（源码片段 + 断点/日志 + 预测对照）
A2 工件：…（三个源文件 + w2 status 与 Plugins 面板记录 + 两份 curl 输出）
A3 工件：…（脚本路径 + node 输出 + 命中断言）
A4 工件：…（两份规则集 + diff + 冲突 curl 证据 + 回滚记录）
A5 工件：…（耗时表 + 合规清单 + 讲解稿 + 四问答案（含认证三道必答题））
隔日复核：日期 / 重跑结果 / 卡住的一步 / 解决方式
结论：达到 / 未达到高级应用水准，依据 = …
```

## 常见问题

**一定要改 Whistle 源码吗？** 不需要改源码，A1 是读与断点观察；A2 是写独立插件（不改主程序）；A3 是调用它暴露的库接口。任何一步都不要求你提交补丁。

**没有团队、没有 CI 也能做 A4 吗？** 能。A4 用两个本机规则集模拟两个人同时修改，冲突与回滚都可以在一台机器上复现。

**高级层和 01–41 源码研读重复吗？** 不重复。01–41 是「讲清楚」，A1–A5 是「用起来并留下可复核证据」；前者是教材，后者是考核。

## 小结

- 高级 = 能改、能集成、能管、能讲清，且每件都有别人能复核的工件。
- 五关各产出一份工件，认证不接受自评，要求隔日复核与可被追问。
- 01–41 在这里从按需回查升级为主要教材。
