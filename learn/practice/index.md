# 实战通关 · 从会开关到能独立解决问题

这份教程的其余 41 篇是**源码研读**：它们讲清楚 Whistle 为什么这样设计，但读完不等于会用。本板块是另一条主线——**以能力为单位的训练关**。目标只有一个：让零基础学习者最终能独立、灵活地把 Whistle 用到真实工作里，遇到没见过的问题也能自己拆开、定位、验证、收尾。

::: tip 先修知识
进入本板块前，请完成 [第 0 站 · 第一次跑通](/guide/quickstart)，并通过它的 11 项通关自检：工具已装好、界面能打开、流量能进来、HTTPS 能看到明文、第一条规则能用开关对照验证生效。除此之外不需要后端服务、不需要真机、不需要团队或 CI 环境——[自造靶子](/practice/target) 会把练习需要的一切用 Whistle 自己造出来。
:::

本板块不占 01–41 的编号：编号是「机制研读」的阅读顺序，训练关按能力等级 L1–L5 排列，**先做后读**，每一关都要求你真的做出一个可观察的结果。

## 本篇的学习目标（可验收）

本篇是**目录与规则说明**，不承载工具操作，操作能力由各训练关逐关验收。读完能自检三条即算达成：① 说出 L1–L5 与[迁移关](/practice/bridge) 各自「能独立完成什么」；② 拿一个现象（例如「规则没生效」）说出该去哪一关、哪一节排查；③ 说清晋级标准只认可观察证据。做不到就先别往下走，回到这一节把能力表再读一遍。

## 通关意味着什么

「会用」不是记住多少协议名，而是能独立完成下面五类工作。晋级标准只认**你做出来的结果**，不认「我看懂了」：

| 等级 | 能独立完成什么 | 关卡 |
|---|---|---|
| L1 看得见 | 让一次请求出现、读懂它的请求与响应、过滤与保存证据，并判断它到底有没有出网 | [L1 观察](/practice/l1-observe) |
| L2 改得动 | 按目标选对指令，精确限定到指定域名/路径/方法，改完用证据确认生效且没误伤别的请求 | [L2 改写](/practice/l2-rewrite) |
| L3 造得出 | 接口没就绪也能联调；把超时、慢响应、偶发 500 变成可重复的必现场景；保存现场并回放 | [L3 构造](/practice/l3-simulate) |
| L4 接得上 | 让 HTTPS/真机/上游/多人协作/CI 这些更复杂的接入方式跑通，并知道各自的边界 | [L4 扩展](/practice/l4-extend) |
| 迁移关 M | 把靶子上练熟的规则换到真实域名、本地服务与 HTTPS 站点，说清必改项与清场 | [迁移关](/practice/bridge) |
| L5 排得清 | 拿到一个模糊现象，独立走完「观察 → 限定 → 构造 → 验证 → 清理」，并判断什么时候不该用 Whistle | [L5 排障](/practice/l5-diagnose) |

完成 [综合通关项目](/practice/final-project) 并在[能力自评矩阵](/practice/final-project#能力自评矩阵) 上全部打勾，才算达到「能灵活应用」。要达到**高级应用水准**，还需继续走 [高级层 A1–A5](/practice/advanced-index) 并通过[高级认证](/practice/advanced-index#高级认证)：读源码、写插件、内嵌集成、协作方案、性能合规与讲解，每关产出别人能复核的工件。

## 为什么先做训练关，再读源码

顺序不是随意排的。零基础者如果先读 01–17，会遇到大量只在源码里存在的对象（`req.rules`、`inspector`、`PipeStream`），却从没在界面上见过它们对应的现象；反过来，先在靶子上把请求发出去、改一遍、验一遍，再回头读机制，每个名词都有东西可对照。

所以本板块与 41 篇的分工是：

| 你在做什么 | 该看哪里 |
|---|---|
| 手上有一个任务要完成 | 本板块对应关卡（给步骤、验收、变式、排障） |
| 做完想知道「为什么这样」 | 关卡末尾的「背后的机制」链接，指向 01–41 对应篇 |
| 忘了某个名词/阈值/配置项 | [概念精解](/concepts/index)、[术语索引](/concepts/glossary)、[速查表](/advanced/reference) |
| 忘了某条指令的完整参数、界面按钮或快捷键 | 官方 `docs/docs/rules/`、`docs/docs/gui/`、`docs/docs/cli.md`；查法见[迁移关](/practice/bridge) 第 4 步 |
| 想改 Whistle 本身、写插件、读实现 | 01–17 源码研读主线、[28 动手实验](/advanced/hands-on)、[29 阅读路线](/advanced/source-reading) |
| 遇到一个真实工程问题，想看设计上的取舍 | [18–27 工程场景](/scenarios/index)（按现象跳读，不必顺读） |

**第 0 站 → 自造靶子 → L1 → L2 → L3 → L4 → [迁移关](/practice/bridge) → L5 → 通关项目 → [高级层 A1–A5](/practice/advanced-index) → 高级认证** 是零基础者的主路线；迁移关负责把练习能力接到真实工作，缺了它就会「只会折腾不存在的域名」；01–41 随时按词回查，不必按编号顺读。已有基础、只想深读源码的人可继续走首页的「按 01–41 顺读」路线，本板块可跳过。

## 每关的固定结构

所有关卡都用同一套格子，读法一致：

1. **本关目标**：一句话说清「做完你能独立完成什么」。
2. **开始前**：承接上一关的状态，列出需要打开什么。
3. **任务**：编号步骤，每条都是能直接执行的动作（命令或界面操作），不用占位域名，不用外部服务。
4. **验收**：明确「该看到什么」和「不该看到什么」，一律以 Network 或终端输出为证据。
5. **变式**：改一个条件再做一遍（换方法、换路径、故意写坏），用来确认你是真会了而不是碰巧。
6. **没看到预期？按顺序查**：操作化的排查清单，不是「去读源码」。
7. **收尾**：关规则、清场，养成不把调试配置留在系统里的习惯。
8. **背后的机制** + **晋级标准**：把刚才做过的事连回源码篇，并给出进入下一关的判据。

## 常见问题

**我没有后端服务、没有测试机、没有手机，能做吗？** 能。[自造靶子](/practice/target) 用 Whistle 自己造出一个可稳定命中、可随时改写的请求，L1–L3 和通关项目全部基于它；L4 里需要真机/团队/CI 的部分都给了本机等价替代做法。

**必须先读完 31–41 概念精解吗？** 不需要。概念精解是**按需回查词典**，不是前置课；卡在某个名词时按链接跳进去看一眼即可。把 360 条术语先背一遍再动手，反而学不会。

**规则和 01–41 里写的不一样怎么办？** 本板块以官方文档 `docs/docs/rules/` 与本仓库 `README.md` 的写法为准，所有规则都在靶子上验证过；若与某篇源码分析的表述不同，以你亲眼看到的结果和官方文档为准。

## 小结

- 目标是「能独立灵活应用」，验收标准是可做出的结果，不是记住的知识量。
- 五关按能力递进，全部复用同一个免后端靶子，逐级累加；L4 之后插入[迁移关](/practice/bridge)，把靶子换成真实域名、本地服务与 HTTPS 站点，避免能力停在练习环境里。
- 41 篇源码研读转为按需回查，不再是零基础者的第一站。
- 每关都要求留证据、做变式、会排障、会收尾——这正是「灵活」与「照抄」的区别。
