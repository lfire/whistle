# 综合通关项目 · 独立搭好一套联调环境

::: tip 先修知识
已完成 [L1–L5](/practice/index)。本项目不再给逐步命令——只给任务、约束和验收标准。请自己决定用哪些规则、怎么验证、怎么收尾。需要的写法都在前面五关里，忘了就按关卡链接回查。
:::

## 任务背景

你正在开发一个页面，它要调用三个接口，但**后端一个都还没部署**：

| 接口 | 期望行为 | 额外要求 |
|---|---|---|
| `practice.test/api/user` | 返回固定用户信息 | 必须来自 Values，方便产品同学改数据 |
| `practice.test/api/order` | 返回订单列表 | 只有 `POST` 才 Mock，`GET` 不受影响 |
| `practice.test/api/pay` | 一半概率返回 500 | 用来验证客户端的错误提示与重试逻辑 |

同时要满足：

1. `practice.test/other` **完全不受影响**（证明没有误伤）。
2. 能验证「接口慢」时客户端的 loading 状态（不依赖真实网络）。
3. 能把一次失败现场保存下来、重放一次、确认重放仍受当前规则影响。
4. 全程不访问任何真实后端，不依赖真机、团队或 CI。
5. 做完清场：关规则、留下的证据归档、取消不再需要的证书信任。

## 约束

- 只能用 [第 0 站](/guide/quickstart) 装好的 Whistle 与 [自造靶子](/practice/target)，不得引入外部服务。
- 每次改动后必须留**可观察证据**（Network 截图/导出的会话/终端输出三选一）。
- 一次只改一个变量；改完做「该变 / 不该变」两发对照。
- 遇到不符合预期，按 [L5](/practice/l5-diagnose) 的六步走，不要直接推翻重来。

## 分阶段验收

### 阶段一 · 环境（承接第 0 站与靶子）

- [ ] `w2 status --all` 显示实例在运行；界面四个 Tab 能打开。
- [ ] `练习靶子` 规则组能打开/关闭，关掉 ON 后 `practice.test` 请求会失败（证明没出网）。
- [ ] 把基线改成 `$practice.test/api` / `$practice.test/other` 精确匹配（或在阶段二开始前删掉基线），确保三个 `/api/*` 接口不被 `/api` 前缀遮蔽。

### 阶段二 · 三个接口（L2 + L3）

- [ ] `/api/user` 返回 Values 里的内容；改 Values 保存后刷新，响应跟着变。
- [ ] `/api/order` 的 `POST` 返回 Mock，`GET` 不受影响（用两种方法的对照输出证明）。
- [ ] `/api/pay` 连发 10 次，约一半返回 500；把概率改成 `chance:1` 后 10 次全失败，再改回。
- [ ] `practice.test/other` 在所有阶段都保持原样（每阶段至少验证一次）。

### 阶段三 · 慢网与现场（L3）

- [ ] 选定一个接口加延迟，Timeline 或终端计时能看出变化；说明延迟卡在转发前还是回写前。
- [ ] Save 一条失败请求、Export 成文件、再 Import 回来。
- [ ] 用 Composer 重放一次，用 `fc:` 筛出；开着/关着 `statusCode://500` 各重放一次，对比两次结果并解释差异。

### 阶段四 · 边界与排障（L4 + L5）

- [ ] 把其中一个接口换成 `https://practice.test/api`，确认能看到明文；关掉 Enable HTTPS 后变成 `Tunnel to`，再恢复。
- [ ] 故意写坏一条规则（例如漏掉 `file://` 内联值的括号），记录报错表现，再按 [L2](/practice/l2-rewrite) 的 7 步定位并修好。
- [ ] 用 `X-Client: phone-sim` 与普通请求各发一次，用 `includeFilter://reqH.x-client:phone` 让改动只对一个客户端生效，留两发对照输出（[L4](/practice/l4-extend) 多客户端）。
- [ ] 分别用 **Rules Export → Import** 和 **`.whistle.js` + `w2 add`** 导入规则集，各自确认界面出现（两者不是一回事）。
- [ ] （选做，需要 Node.js）起一个独立实例 `w2 start -p 8100 -S practice2`，用 `w2 status --all` 看到两个实例，用完 `w2 stop -S practice2`。不做不影响通关。
- [ ] 自己造一个**教程里没出现过的现象**（例如「某接口偶发返回旧数据」），按 [L5](/practice/l5-diagnose) 六步写一份排查记录：观察证据、至少两个假设、分别怎么证伪、结论落在哪一层、怎么清场。
- [ ] 对照 [L5「什么时候不该用」](/practice/l5-diagnose) 的 5 条勾选清单逐条给结论。

### 阶段五 · 收尾

- [ ] 关掉所有规则组的 ON，或删除演练规则。
- [ ] 证据文件归档；`w2 status --all` 无多余实例。
- [ ] 按 [第 0 站](/guide/quickstart) 通关自检第 11 项取消不再需要的根证书信任。

### 阶段六 · 开放题（证明「灵活」而不是「照抄」）

前五阶段都有清单，只能证明你会执行；[迁移关](/practice/bridge) 已经给过一次带步骤的换域名示范。下面三题没有标准答案，用来证明你能**独立迁移**：

1. **自定目标**：想一个本教程没写过的联调需求（例如「只让某个特定请求头携带的接口返回维护中」），独立设计一套规则集（至少 3 行，含范围限定与兜底），写出每行意图、验收方式与清场步骤。
   **判据**：① 至少 3 行且有一行是限定、一行是兜底；② 两发对照能证明「该变 / 不该变」；③ 能用 `curl` 或 Network 说出每行生效的证据。
2. **换全新域名迁移**：把整套方案从 `practice.test` 迁到你自己选的域名/路径，说明哪些行必须改、哪些不用改、最容易漏的是哪一处。
   **判据**：① 换完后三条请求都能复现原来的结果；② 明确写出「pattern 必改、操作不必改、ON/收尾最容易漏」；③ 至少做一次「故意漏 `$`」并观察到误伤。
3. **判断不用**：给一个模糊需求（例如「线上偶发超时，想长期监控」），先判断该不该用 Whistle；写出至少 3 类不该用的场景与理由，再说明如果只做短期排查，边界在哪、怎么收尾。
   **判据**：① 对照 [L5](/practice/l5-diagnose)「什么时候不该用」的 5 条勾选清单逐条给结论；② 短期排查写明「只观察不改写 / 有结束时间 / 结束清场」三条准入；③ 能说清替代手段（日志、观测、契约测试）分别用于哪一类需求。

## 阶段六的工件与复核（证明「不是照抄」）

开放题不能只靠自评打勾，必须留下**别人也能按着复现的工件**：

1. **规则集文件**：把开放题 1 的规则集导出或存成 `my-rules.txt`，写明每行意图、适用范围、兜底与清场步骤。
2. **迁移 diff**：把开放题 2 的改前/改后两份规则并排放，标出「必须改 / 不必改 / 最容易漏」三处。
3. **判断说明**：开放题 3 写成一页，含 5 条勾选清单的逐条结论、短期排查的四条准入、替代手段的分工。
4. **隔日复核**：把三份工件放一天后再拿来，不看教程、只照工件把规则集重新跑通一次，记下哪一步卡住、为什么。能一次跑通，才说明是「自己设计的」而不是「记住了教程里的三行」。

复核不通过就回到对应关卡重做变式、把卡住的那一步补进工件，再复核一次——**卡住本身不是失败，能定位并补上才是证据**。这一步是通关与「照单执行」的分界线。

## 能力自评矩阵

每项只有在**你独立做出过可观察结果**时才打勾，不要凭「我看懂了」打勾。

| 能力 | 判据 | 对应关卡 |
|---|---|---|
| 装好并启动工具、打开界面 | `w2 -V` / `w2 status` / 四个 Tab | [第 0 站](/guide/quickstart) |
| 让流量经过代理并看到请求 | Network 出现目标、关 ON 反证 | [靶子](/practice/target)、[L1](/practice/l1-observe) |
| 点开请求读懂请求/响应、过滤、存证 | 能说清各面板、会用两种前缀、会 Save | [L1](/practice/l1-observe) |
| 按目标选指令并验证生效 | 每类改写都能给出前后对照 | [L2](/practice/l2-rewrite) |
| 精确限定、证明没误伤 | pattern + 过滤器 + 对照组 | [L2](/practice/l2-rewrite) |
| 规则没生效能自己定位 | 能走完 7 步排查并给出原因 | [L2](/practice/l2-rewrite)、[L5](/practice/l5-diagnose) |
| 接口未就绪也能联调 | Values + `file://{key}` 造契约 | [L3](/practice/l3-simulate) |
| 把偶发/慢网/中断变成必现 | 延迟、状态码、`chance` 各做过一次 | [L3](/practice/l3-simulate) |
| 保存现场并反复重放 | Save / Export / Composer / `fc:` | [L3](/practice/l3-simulate) |
| 判断 HTTPS 能不能改、在哪层改 | `Tunnel to` 三层排查、`disable://capture` | [L4](/practice/l4-extend)、[L5](/practice/l5-diagnose) |
| 按客户端/规则集扩展 | 过滤客户端、`w2 add` 导入规则集（内嵌实例为选做） | [L4](/practice/l4-extend) |
| 模糊现象独立走完六步 | 观察→限定→构造→验证→结论→清理 | [L5](/practice/l5-diagnose) |
| 知道什么时候不该用 | 能给出至少 3 类反例与理由 | [L5](/practice/l5-diagnose) |
| 每次都清场 | 关规则、停实例、取消证书信任 | 全部关卡 |
| 迁移与自主设计 | 能把整套方案换到新域名、自定目标设计规则集、判断何时不用 | [阶段六](#阶段六--开放题证明灵活而不是照抄) |

## 通关标准

**五个阶段 + 阶段六三道开放题全部完成 + 能力矩阵全部打勾**，并且开放题是你自己设计、不是照抄教程，才可以声称能独立、灵活地把 Whistle 用到真实工作里。只会照单执行清单，不算通关。此时再回头读 01–41 源码研读，你会带着一堆亲手做过的现象去看机制，效率与只顺读完全不同。

如果矩阵里还有没打勾的项，或阶段六的开放题写不出自己的方案，回到对应关卡把那一关的「变式」重做一遍——**通关看的是做出来的结果，不是读完的篇数**。

## 小结

- 本项目把 L1–L5 串成一条完整链路：环境 → 改写 → 构造 → 边界 → 收尾。
- 验收一律用可观察证据，不许用「理解了」代替「做出来了」。
- 清场是通关的一部分：能不留痕地退出调试，才算真的能独立工作。
