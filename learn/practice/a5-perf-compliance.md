# A5 说得清 · 性能、合规与把机制讲明白

::: tip 先修知识
已完成 [A1–A4](/practice/advanced-index)，能读源码、写插件、内嵌集成、管理多人规则集。本关不需要新工具，只要 `curl`、`w2` 与一台能写文档的机器。
:::

## 本关目标

对「用 Whistle」这件事给出**量化代价**与**可判断的合规边界**，并把「为什么」讲给一个会追问的人。做完你能对一套方案负责地签字，而不是只会说「挺好用的」。

## 开始前

1. `w2 start` 在跑、`练习靶子` 基线可用。
2. 准备一个能稳定响应的本机服务：`python3 -m http.server 5173`（另一个终端）。
3. 准备好 [27 边界与合规](/scenarios/boundaries) 与 [L5「什么时候不该用」](/practice/l5-diagnose) 作对照。

## 任务

### 第 1 步 · 量化代理开销

用 `curl -w` 记录三种情况各 10 次的 `time_total`（`-o /dev/null` 丢掉响应体）：

```sh
# A 直连本机服务
for i in $(seq 1 10); do curl -s -o /dev/null -w "%{time_total}\n" http://127.0.0.1:5173/; done
# B 经代理但不命中规则（换一个没被规则覆盖的路径）
for i in $(seq 1 10); do curl -s -o /dev/null -w "%{time_total}\n" -x 127.0.0.1:8899 http://127.0.0.1:5173/; done
# C 经代理且命中规则（靶子短路）
for i in $(seq 1 10); do curl -s -o /dev/null -w "%{time_total}\n" -x 127.0.0.1:8899 http://practice.test/api; done
```

`seq 1 10` 表示循环 10 次，`-w "%{time_total}"` 打印单次耗时。把每组输出存成文件再算（**偏差 = 每个测值与本组平均值之差的绝对值的最大值**）：

```sh
for i in $(seq 1 10); do curl -s -o /dev/null -w "%{time_total}\n" -x 127.0.0.1:8899 http://practice.test/api; done | tee C.txt
awk '{s+=$1; a[NR]=$1} END{avg=s/NR; for(i=1;i<=NR;i++){d=a[i]-avg; if(d<0)d=-d; if(d>max)max=d} printf "平均 %.4f 秒，最大偏差 %.4f 秒\n",avg,max}' C.txt
```

把 30 个数与三组「平均 / 最大偏差」记成表。**必须写明测量条件**（本机、无网络往返、单机单次），并说明为什么这个结论**不能**直接推到生产环境——代理会改变连接复用、延迟特征与缓存行为（[27](/scenarios/boundaries) 明确性能基准不该用代理测）。

### 第 2 步 · 给出合规结论

对照 [L5 的 5 条勾选清单](/practice/l5-diagnose)（这是「该不该用」的判据；[27](/scenarios/boundaries) 另有一份更细的合规清单，两者不是同一份），对下面三个场景逐条给结论：

| 场景 | 该不该用 | 理由（对应哪一条） | 替代手段 |
|---|---|---|---|
| 本地联调，只改自己负责的接口 | | | |
| 线上偶发超时，想长期监控 | | | |
| 生产域名、他人设备上的 HTTPS 抓包 | | | |

再补一段「短期只读排查」的四条准入（只观察不改写 / 只对自己负责的服务 / 有结束时间 / 结束即清场），并写明收尾动作（`w2 proxy 0`、`w2 stop`、取消根证书信任、关规则）。

### 第 3 步 · 写一页机制讲解稿

题目自定（例如「为什么装了根证书仍可能看不到 HTTPS 明文」）。要求：

1. 有一段面向**没用过代理的人**的类比；
2. 有一段面向**工程师**的机制说明，必须指向具体源码或实验（例如 `lib/tunnel.js:202-215` 的 `isIntercept()`、[10](/core/connect-mitm)）；
3. 有一段「代价与边界」；
4. 附**四个追问的答案**（前三个是[高级认证](/practice/advanced-index#高级认证)的必答题，必须指向具体源码或具体实验，不许只写结论）：
   - 为什么装了根证书仍可能看不到 HTTPS 明文？解密判定发生在哪一段（`isIntercept()` / 两段 TLS）？
   - 为什么改一行规则会导致整份规则集重新编译？这对多人协作意味着什么（[25](/scenarios/collab-config)）？
   - 什么时候不该用 Whistle？给三个可判断的触发条件与替代手段。
   - 为什么 `Tunnel to` 不是抓包失败？

### 第 4 步 · 产出工件

`a5-perf-compliance/`：① 30 个耗时数据与三列平均/偏差表；② 三个场景的合规结论表 + 四条准入；③ 一页讲解稿 + 四问答案（含认证三道必答题）；④ 收尾动作清单；⑤ 「隔日复核」记录。

## 验收（工件可复核）

**该看到**：三组数据各 10 次、平均值写清、测量条件与「不能推到生产」的说明都有；合规表逐条对应 5 条勾选；讲解稿同时有类比、源码指向、代价边界与四问答案；工件齐全。

**不该看到**：只测一次就说「代理慢 X 倍」；合规结论只写「注意安全」；讲解稿全是结论、没有源码或实验支撑；追问答案回避「为什么」。

## 变式

1. **加规则复杂度**：把规则从 1 行加到 20 行，重测 C 组，看耗时是否变化并解释。
2. **加 body 大小**：让 Values 内容从几十字节变成几百 KB，重测并观察阈值（[12](/core/capture-data) 的 1MB/2MB/16MB）。
3. **换追问**：让同伴（或自己隔天）提一个讲解稿里没覆盖的问题，补进稿子并标注依据。

## 没看到预期？按顺序查

1. 数据波动大 → 增加次数、记录最大偏差，不要只报平均值。
2. B 组没走代理 → `-x` 端口是否与 `w2 status` 一致。
3. 合规表写不出理由 → 回 [27](/scenarios/boundaries) 与 [L5](/practice/l5-diagnose) 的勾选清单。
4. 讲解稿被追问卡住 → 回 [A1](/practice/a1-source) 用源码/断点补证据，不要凭记忆答。

## 收尾

停掉 `python3 -m http.server`（`Ctrl+C`），关掉靶子 ON，按第 2 步的收尾清单检查一遍。保留工件目录。

## 隔日复核

第二天只看工件，重新测一组数据、复述一次讲解稿并回答四问，记录哪一步卡住、怎么解决。
