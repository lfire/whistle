# L5 排得清 · 从现象到结论的独立排查

::: tip 先修知识
已完成 [L1–L4](/practice/index) 与 [迁移关](/practice/bridge)，能看全请求、精确改写、造现场、接复杂环境，并把规则迁到真实目标。本关不再教新指令，只练**面对没见过的问题时怎么想**。
:::

## 本关目标

拿到一个模糊现象（「页面白屏」「只有 Tunnel to」「规则没生效」「手机连不上」），你能独立走完六步并给出可复现的结论，还能判断「这件事根本不该用 Whistle 解决」。灵活应用的标志不是会写多少规则，而是**能定位、能证伪、能收尾**。

## 开始前

1. 已完成 [L1–L4](/practice/index)，`练习靶子` 基线可用、能随时开关 ON。
2. 手边有 [L1](/practice/l1-observe) 存下的会话或导出文件，用来练案例里的「固定现场」。
3. 准备一个记录方式（截图、Save 的会话或终端输出）——本关的验收只认证据，不认「我想明白了」。

```txt
观察 → 限定 → 构造 → 验证 → 结论 → 清理
```

1. **观察**：让现象在 Network 里出现，点开看请求/响应/状态码/耗时，先别改任何东西。
2. **限定**：把它缩小到「哪个域名 / 哪条路径 / 哪个方法 / 哪个客户端」，其余流量作为对照。
3. **构造**：用 L3 的规则把现象变成稳定必现，或关/开 ON 做反证。
4. **验证**：一次只改一个变量，看变化是否符合假设；不符合就换假设。
5. **结论**：写出「因为 X，所以在 Y 层做 Z」，并说明边界。
6. **清理**：关规则、取消证书信任、停实例——留着调试配置会污染下一个问题。

## 任务

本关不教新指令，只做三件事，每件都要留下可核对的证据：

1. 把「万能六步」写在纸上，对着下面的决策树走一遍，确认每个分支都有能立即执行的动作（发一发请求、开关 ON、看一条响应头），而不是「去读源码」这类无法验收的步骤。
2. 从 14 个案例里挑至少 6 个（含至少 2 个本机可直接复现；需要真机/团队的案例用 L4 等价替代或标注「本机无法复现」），逐个按本关统一的「观察 → 限定 → 构造 → 验证 → 结论 → 清理」六步做完，每个留一条 Network 截图、Save 的会话或终端输出。
3. 完成「变式」的 4 个练习，再用「什么时候不该用」的 5 条勾选清单自评。

## 万能六步

全站排障统一用这一套命名，后面每个案例的字段都按它对齐：

```txt
观察 → 限定 → 构造 → 验证 → 结论 → 清理
```

1. **观察**：让现象在 Network 里出现，点开看请求/响应/状态码/耗时，先别改任何东西。
2. **限定**：把它缩小到「哪个域名 / 哪条路径 / 哪个方法 / 哪个客户端」，其余流量作为对照。
3. **构造**：用 [L3](/practice/l3-simulate) 的规则把现象变成稳定必现，或关/开 ON 做反证。
4. **验证**：一次只改一个变量，看变化是否符合假设；不符合就换假设。
5. **结论**：写出「因为 X，所以在 Y 层做 Z」，并说明边界。
6. **清理**：关规则、取消证书信任、停实例——留着调试配置会污染下一个问题。

## 决策树：能不能改、在哪层改

```txt
请求根本没出现在 Network？
├─ 是 → 流量没经过代理。查系统代理/扩展/-x 端口/实例是否活着（第 0 站第 3 步）
└─ 否 ↓
只有一条 Tunnel to？
├─ 是 → 纯透传。查「入口→信任→判定」三层：根证书信任、Enable HTTPS、disable://capture（第 0 站第 4 步）
└─ 否 ↓
能看到明文但规则没生效？
├─ 是 → 按 L2 的 7 步：ON/Save/分组 → pattern → 行序 → 过滤器 → Values key → 请求/响应期 → 解密
└─ 否 ↓
改了但改错对象/影响过大？
├─ 是 → pattern 写宽了。收紧到具体路径，用 includeFilter/excludeFilter 二次限定，做「没误伤」对照
└─ 否 ↓
请求能发出，但页面仍白屏 / 报 CORS / 返回 401？
├─ 是 → 先读响应头与状态码：若响应来自源站且规则根本没命中，这多半不是代理层问题，转客户端日志或服务端观测
└─ 否 ↓
现象只在特定网络/客户端/概率下出现？
├─ 是 → 用 L3 把条件写成规则（reqDelay/statusCode/chance/includeFilter://m:*），变成必现
└─ 否 → 用 Save/Export 固定现场并重放；若按 7 步证伪两次以上仍无变化，判定「不是代理层问题」，清场后转日志/观测/契约测试，不要继续堆规则
```

## 14 个真实故障案例

每个案例都按统一的六步给出，字段对应如下：**现象 = 观察**、**观察清单 / 假设 = 限定**、**构造 = 构造**、**该看到 = 验证**、**解法 / 边界 = 结论**、**清理 = 清理**。所以案例里写「解法」不是另起一套流程，它就是六步里的第五步。请用 [自造靶子](/practice/target) 或你自己的目标逐条做一遍，不要只看。

### 1. 抓包列表里只有 `Tunnel to`

- 观察：状态码、是否有 SNI、目标端口是不是 443、客户端是谁。
- 假设：HTTPS 未解密；构造：对同一域名开/关 `enable://https` 做对照。
- 解法：按第 0 站第 4 步补根证书信任 + Enable HTTPS。
- 边界：若目标用了证书固定或 mTLS，应 `practice.test disable://capture` 放行，不要绕过。
- 清理：关掉临时 `enable` 规则。

### 2. 浏览器提示证书不受信

- 观察：是系统浏览器还是 Firefox；证书是否已下载。
- 假设：只下载没设为「始终信任」；构造：换一个 `.cer` / `.pem` 格式重试。
- 解法：系统证书库设为始终信任；Firefox 单独导入或开 `security.enterprise_roots.enabled`。
- 边界：只对自己有权调试的流量装根证书。
- 清理：用完取消信任。

### 3. 写了规则却完全没生效

- 观察：Network 里点开看**完整 URL**（别凭记忆写 pattern）。
- 假设：ON 关着 / 选错分组 / pattern 不匹配 / 被前面规则先命中。
- 构造：把 pattern 临时写成整域名，确认能命中后再逐步收紧。
- 解法：按 L2 的 7 步逐项排除；`lineProps://important` 可改变行序。
- 边界：默认每协议首条命中即返回，不是「所有规则都执行」。
- 清理：删掉临时宽规则。

### 4. 规则生效了，但把其它接口也改了

- 观察：列出受影响的所有 URL。
- 假设：pattern 写成整域名；构造：给靶子加 `/other` 对照组。
- 解法：收紧到具体路径，或 `excludeFilter://*/static` 排除；每次改动都做「没误伤」验证。
- 边界：规则集可以多选，确认当前选中的是哪组。
- 清理：保留精确规则，删宽规则。

### 5. 接口返回 500，但后端说没收到请求

- 观察：响应头、响应体、Timeline 有没有出站耗时。
- 假设：`statusCode://` 或 `file://` 短路了转发；构造：关掉 ON 再发一次。
- 解法：确认这是自己造的 Mock/错误场景，不是后端故障。
- 边界：Mock 期间不要拿这个响应去判断后端逻辑。
- 清理：关 Mock 规则。

### 6. 请求很慢，时快时慢

- 观察：Timeline 里时间花在转发前还是回写前。
- 假设：`reqDelay` / `resDelay` / `chance` 还在生效。
- 构造：搜 `reqDelay|resDelay|chance` 检查所有规则组。
- 解法：关掉演练规则；若确需弱网，明确写在独立规则组里。
- 边界：`chance` 是统计近似，不能当确定性断言。
- 清理：清掉延迟/概率规则。

### 7. 手机连不上代理

- 观察：手机与电脑是否同网段、防火墙是否放行端口、证书下载用的 IP 是否可达。
- 假设：代理地址填错或端口被拦；构造：在电脑本机 `curl -x` 同一地址先验证代理本身通不通。
- 解法：Wi-Fi 手动代理填电脑 IP:8899，iOS 两步信任。
- 边界：没有真机时，用 [L4](/practice/l4-extend) 第 3 步的多客户端等价练法。
- 清理：手机用完关代理、取消证书信任。

### 8. HTTPS 里某个 App 报 `captureError`

- 观察：是不是只有这个 App；有没有 SNI。
- 假设：证书固定或双向认证；构造：换一个普通浏览器访问同一域名对照。
- 解法：`practice.test disable://capture` 放行不解密。
- 边界：不要尝试绕过 pinning / mTLS。
- 清理：保留放行规则或删除。

### 9. 改了规则文件，界面迟迟不更新

- 观察：改的是本地文件、`@` 远程 URL 还是 Values；等了多久。
- 假设：界面靠轮询感知变化，不是推送。
- 构造：手动刷新界面 / 等一个刷新周期；改一个显眼的值便于确认。
- 解法：确认 `w2 add` 导入的是当前选中的规则集；远程规则有刷新间隔。
- 边界：最终一致，不适合要求瞬时生效的验证。
- 清理：无。

### 10. 现象只在真机/特定浏览器出现

- 观察：User-Agent、请求头、协议版本（HTTP/2、WebSocket）。
- 假设：客户端差异或协议差异；构造：用 `includeFilter://reqH.user-agent:/.../i` 把条件写成规则，在桌面复现。
- 解法：把「偶发条件」变成可重复的构造，再逐项排除。
- 边界：H2 会被降级到 H1 再改写，某些帧级行为不能简单复现（[04](/domain/web-protocols)）。
- 清理：删掉条件规则。

### 11. `w2 start` 起不来，或起的是另一个实例（需先做过 L4 变式 2）

- 观察：`w2 status --all` 列出哪些 PID / Port / Storage；目标端口是否被别的程序占用。
- 假设：端口冲突，或之前用 `-S` 起过独立存储目录的实例，你现在看的是另一个界面。
- 构造：换端口 `w2 start -p 8100 -S practice2`，再用 `curl -x 127.0.0.1:8100` 打一发。
- 解法：确认 `curl` 的 `-x` 端口、浏览器代理设置、界面地址三者指向同一个实例；多实例时 `w2 stop -S <目录名>` 精确停止。
- 边界：`w2 stop` 只停默认实例，带 `-S` 的实例必须同名停止。
- 清理：停掉不用的实例，`w2 status --all` 复核。

### 12. `curl -x` 能抓到，浏览器却抓不到

- 观察：`curl` 那发出现在 Network，浏览器的没有。
- 假设：浏览器没走代理——ZeroOmega 情景没切、系统代理被 `w2 proxy 0` 关了、公司 VPN / PAC 把流量绕走。
- 构造：保持浏览器开着，用 `w2 proxy` 打开系统代理再刷新一次做对照。
- 解法：确认扩展情景、系统代理开关、PAC 规则；HTTPS 目标还要确认证书信任。
- 边界：公司网络的上游代理/VPN 策略不要擅自绕过，按 [02](/domain/proxy-basics) 的上游代理方式处理。
- 清理：关掉临时改的系统代理设置。

### 13. 规则明明写对了，却因为「规则集没选中」不生效

- 观察：Rules 面板里当前勾选/选中了哪几组；ON 是否红色。
- 假设：新建的组没被选中，或多选时另一组覆盖了它。
- 构造：只选中这一组、Save、发一发；再多选一组做对照。
- 解法：按 [L2](/practice/l2-rewrite) 第 2 步确认当前生效的规则集；成对辨析见 [39](/concepts/08-confusions)。
- 边界：界面靠轮询感知规则集变化，不是瞬时推送。
- 清理：只保留当前任务需要的组。

### 14. 现象其实不在代理层（白屏 / CORS / 401）

- 观察：响应头里 `Access-Control-Allow-Origin`、状态码 401/403、响应体是不是源站给的。
- 假设：这是浏览器的跨域策略或鉴权问题，代理既没改请求也没改响应。
- 构造：关掉所有规则组 ON 再发一次——若现象完全一致，就证明与 Whistle 无关。
- 解法：清场，转客户端日志、服务端观测或接口测试；不要继续加规则试图「修好」它。
- 边界：这正是「什么时候不该用 Whistle」里最常被忽略的一类。
- 清理：关全部规则，记录一次「判定为非代理问题」的结论。


## 变式

把六步用到没练过的条件上，每个变式都留一条证据：

1. **换客户端**：给请求加 `X-Client: phone-sim`，用 `includeFilter://reqH.x-client:phone` 把改动只限定到它，观察另一个客户端不受影响。
2. **换协议**：把靶子换成 `https://practice.test/api`，走一遍「只有 Tunnel to」的决策分支，确认自己能说清是「信任」还是「判定」没到位。
3. **故意写坏**：漏掉 `file://` 内联值的括号、把 `$` 精确匹配写成宽匹配，让规则误伤 `/other`；再用「限定 → 构造 → 验证」把原因找出来，而不是直接重写规则。
4. **反向练习**：挑一个案例，先写出「这件事不该用 Whistle」的理由，再说明如果一定要用，边界与收尾分别是什么。

## 什么时候不该用 Whistle

会判断「不用」和会用同样重要。**下面任一条打勾，就不要用 Whistle 硬撑**：

- [ ] 目标是生产域名、他人设备或无授权的系统。
- [ ] 需要长期生效、跨天留存，或作为团队常态配置。
- [ ] 你要验证的是后端真实逻辑、数据一致性或性能基准（代理会改变连接与延迟特征，测出来的数不可信）。
- [ ] 目标用了证书固定 / 双向认证 / 系统级保护。
- [ ] 你无法在结束后确认「规则已关、证书信任已取消、额外实例已停」。

**边界模糊时怎么判**：线上偶发问题做**短期只读排查**是允许的，但要同时满足四条——只观察不改写、只对自己负责的服务、有明确结束时间、结束即清场并留记录。一旦需要改响应、留存数据或跨天生效，就交给服务端观测、日志或契约测试，别把调试代理当长期方案。[27《能力边界、风险与合规》](/scenarios/boundaries) 给了完整的合规清单。

## 验收

**该看到**：每个案例都留下一条可核对的证据（Network 截图、Save 的会话或终端输出），并能指着它说明「观察到了什么、假设是什么、用什么构造验证、结论是哪一层」；对至少 3 个案例能独立写出「不该用 Whistle」的理由。案例 2 / 7 / 8 / 10 依赖浏览器、真机或 pinning，手边没设备时用 [L4](/practice/l4-extend) 的多客户端等价做法，或明确标注「本机无法复现」，不要凭想象填结论。

**不该看到**：一上来就改规则却不先看请求；一次改多个变量导致无法归因；查完不关规则。

## 没看到预期？按顺序查

1. 现象没在 Network 出现 → 回到 [L1](/practice/l1-observe) 的「流量没经过代理」排查，别急着改规则。
2. 按 7 步改了仍无变化 → 做一次「关掉全部 ON」的反证；若现象完全一致，判定为**非代理层问题**。
3. 已证伪两个假设仍无解 → 停下来清场，转客户端日志 / 服务端观测 / 契约测试，不要再堆规则。
4. 案例需要真机、团队或 pinning → 用 [L4](/practice/l4-extend) 的多客户端等价做法，或明确标注「本机无法复现」，不要凭想象写结论。
